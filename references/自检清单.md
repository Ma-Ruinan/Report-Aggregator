# 自检清单

综合报告生成后，**必须**逐项过本清单，拿成品回源比对子报告。五类自检：数值、逻辑、表述、图表、口径。

---

## 一、数值核对

逐表、逐句比对成品与子报告原文，确认：

- [ ] 成品中每个数字，是否在子报告中**真实出现**（不新增任何子报告没有的数字）。
- [ ] 每个数字是否被放在了**正确的章节/表格**（无误置、无张冠李戴）。
- [ ] 归纳转述时是否发生了**数值偏移**（如 3.96 抄成 3.97、86.45% 抄成 86.5%）。
- [ ] 差值方向是否一致（如统一为「B-A」，全文固定，不一会 B-A 一会 A-B）。
- [ ] 汇总类数字（合计、平均、通过率）是否与子报告的分项能对上（如 26 黑 + 27 白 = 53，通过率 100%）。

**红线**：不得编造、不得凭理解加工、不得擅自统一子报告自身的矛盾数值。

---

## 二、逻辑核验

审视「数据 → 结论」的推理是否成立：

- [ ] 结论是否都能在子报告原文找到**对应表述**，有无额外拔高、放大。
- [ ] 有无「**样本量过小却下比率性结论**」的问题（如「2 条用例全漏」说成「拦截率 0%」——应补一句样本量限定）。
- [ ] 有无「**口径限定被弱化**」的问题（如子报告说「绝对时延只作量级参考，因上游模型不同」，综合提炼时却把时延优势说成产品优势）。
- [ ] 有无「**用 1 道题/1 轮**去论证一个跨任务的类别化结论」（如智慧巡察仅 1 题却概括为「B 在这类任务上更强」）——应补样本量说明。
- [ ] 归纳转述是否产生了子报告**没有的新结论**。

**红线**：不做跨口径的强行合成，不给子报告没有的结论，不忽略子报告自带的限定语。

---

## 三、表述核验

- [ ] 改写后的表述是否**可理解**（专业但不需要揣测）。
- [ ] 改写后是否**改变了原意**（逐句回头比对）。
- [ ] 抽象/生僻词是否清除（「分水岭」「反向短板」「拉动」「归一化」「provenance」「门禁」「冻结」等）。
- [ ] 专业术语（TTFT、TPOT、p 值等）是否在首次出现时给了**通俗解释**。
- [ ] 加粗的重点句是否读得懂（加粗句是最容易被写得抽象的地方，重点检查）。

---

## 四、图表完整性

- [ ] 子报告中的图是否**全部提取并保留**（除非经制作人确认删除）。
- [ ] 每张图是否放在**正确的章节**（图 ↔ 维度映射无误）。
- [ ] 图注编号是否**连续、统一**（如「图 3-1 ~ 图 7-7」）。
- [ ] 图内数据是否**未做任何改动**（允许的只是裁掉烤入的标题条、统一配色等样式级处理）。
- [ ] 安全/敏感类图表若原本烤入了自己的编号，是否已做样式处理并统一编号。

---

## 五、口径声明

- [ ] 不同能力面的**口径差异**是否如实交代（评分尺度、样本规模、上游条件）。
- [ ] 是否**没有**跨口径强行合成单一分数。
- [ ] A/B 命名口径是否全文统一，且在某处**显式声明**一次。
- [ ] 「子报告」与「风格参考报告」是否区分清楚（后者不提供数据、不纳入结论）。
- [ ] 安全/性能等「性质不同」的多个测试结果是否**分别陈述、不混同**。

---

## 交付前最后确认

- [ ] 已形成一份「自检结论」。
- [ ] 已列出「**待人工判断的点**」（源报告自身矛盾、口径是否统一、某图是否保留/裁剪等）。
- [ ] 成品 + 自检结论 + 待判断点，三者一起交付，而非只给成品。
